# gygy-club-core  

Виртуальный клуб с мультиязычным интерфейсом, системой цифровых паспортов резидентов и набором интерактивных локаций (Холл, Бар, Студия, Офис, AI-комнаты).

Это архитектурное переиздание проекта: переход от монолитного кода к событийно-ориентированной модульной системе (Event-Driven Architecture). Предыдущая версия — [`gy-gy-club`](#) — архивирована и сохранена как история.

## Почему новый репозиторий

Старая кодовая база разрослась органически: файлы создавались по мере необходимости без единого контракта между ними. Это привело к:
- смешению стилей модулей (`window.X` глобальные объекты вместе с ES `import/export` в разных файлах);
- прямым обращениям к `localStorage` в обход единого хранилища;
- отсутствию отписки от событий (`destroy()` не реализовывался);
- расхождению между `ARCHITECTURE.md` и фактическим кодом.

Этот репозиторий строится с нуля по единому контракту — см. ниже.

## Архитектурные принципы

1. **Событийно-ориентированная архитектура.** Модули не вызывают друг друга напрямую. Всё взаимодействие — через `core/eventBus.js` (`emit` / `on` / `off`).
2. **Единый источник правды.** Все персистентные данные (паспорт резидента, язык, роль) читаются и пишутся только через `core/storage.js`. Прямые вызовы `localStorage` в модулях и на страницах запрещены.
3. **Контракт жизненного цикла.** Каждый модуль в `modules/` экспортирует объект с методами:
   - `init(container)` — подписка на события, рендер в переданный DOM-контейнер;
   - `update(data)` — реакция на изменение состояния;
   - `destroy()` — отписка от всех событий, очистка DOM и памяти.
4. **Только ES-модули.** Никаких глобальных `window.X`. Всё — `export` / `import`.
5. **Тонкие страницы.** HTML-файлы содержат разметку и один `<script type="module">`, который импортирует нужные модули и инициализирует их. Логика в разметку не встраивается.
6. **Версия и дата — в самом коде.** Каждый файл начинается с шапки-комментария с номером версии и датой правки (см. шаблон ниже). Так текущее состояние проекта всегда видно прямо в исходниках, без сверки с отдельным документом, который легко забыть обновить.

```js
/**
 * core/eventBus.js
 * v1.0.0 — 2026-08-26
 * Шина событий проекта (Pub/Sub).
 */
```

## Структура репозитория

```
core/               → ядро: eventBus, storage, localization
modules/             → независимые узлы комнат и функций (init/update/destroy)
pages/               → HTML-страницы (index, identity, hall, bar, studio, office...)
CONTRACT.md          → формальные правила для модулей (что обязан делать каждый узел)
tools/               → служебные скрипты, включая генератор карты модулей
```

## Карта модулей

Вместо вручную поддерживаемого документа с описанием всех файлов используется скрипт `tools/build-map.js`, который сканирует `core/` и `modules/` и выводит актуальный список файлов с их версией и экспортируемым интерфейсом. Запускать после значимых изменений:

```bash
node tools/build-map.js
```

Проект в активной разработке. Актуальный список готовых модулей — в выводе `tools/build-map.js`, а не в этом README.
