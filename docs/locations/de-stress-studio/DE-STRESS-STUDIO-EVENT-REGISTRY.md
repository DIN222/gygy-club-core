**Версия:** 1.0.0  
**Дата:** 12 ноября 2026  
**Проект:** GY-GY Club  
**Локация:** De-Stress Studio  
**Статус:** Архитектурный документ

---

## 1. Назначение документа

Реестр событий определяет, какие события возникают в De-Stress Studio, какие из них фиксируются системой, для каких целей используются и где хранятся.

Основные задачи:

- обеспечить наблюдаемость работы локации;
- обеспечить контроль операций с публикациями;
- поддерживать модерацию и управление;
- формировать достоверную обезличенную аналитику;
- обеспечивать обратную связь с OFFICE;
- предоставлять основу для развития GY-GY NEWS;
- не допускать избыточного сбора персональных данных.

Реестр является частью архитектуры GY-GY Club.

---

## 2. Основные принципы

### 2.1. Разделение событий

Все события разделяются на две основные категории:

**А. Операционные события**

Возникают при работе с конкретными объектами и операциями клуба.

Примеры:
- создание публикации;
- изменение статуса;
- назначение авторства;
- номинация;
- голосование;
- удаление публикации;
- административное действие.

Операционные события могут содержать технические идентификаторы объектов, необходимые для выполнения операций.

**Б. Аналитические события**

Используются для изучения общей работы локации.

Примеры:
- открытие локации;
- использование функциональных блоков;
- количество выполненных действий;
- динамика предложений;
- агрегированные показатели активности.

Аналитические события не должны содержать прямые идентификаторы участников и исходные тексты пользовательских публикаций.

### 2.2. Минимизация данных

Система фиксирует только те сведения, которые необходимы для конкретной цели.

Не допускается:
- постоянное отслеживание перемещений конкретного участника;
- скрытое чтение буфера обмена;
- сбор содержимого внешних сообщений;
- создание персональных психологических профилей;
- сбор технических характеристик устройства ради скрытой идентификации;
- объединение аналитических событий с Passport ID без отдельного обоснования.

### 2.3. Управление

AI может анализировать разрешённые данные, выявлять тенденции, прогнозировать возможные проблемы и формировать рекомендации.

AI не получает права самостоятельно изменять рабочие данные, удалять публикации, назначать статусы или принимать административные решения без предусмотренного полномочия.

Операционные решения остаются под контролем человека.

## 3. Существующая техническая основа

В проекте предусмотрен модуль:

`modules/destressStudioEvents.js`

В его текущем перечне определены следующие события:

| Событие | Назначение |
|---|---|
| `MODULE_INIT` | Инициализация модуля |
| `DESTRESS_STUDIO_OPENED` | Открытие De-Stress Studio |
| `DESTRESS_STUDIO_LEFT` | Выход из De-Stress Studio |
| `MODULE_DESTROY` | Завершение работы модуля |
| `SITUATION_SELECTED` | Выбор ситуации |
| `PHRASE_CREATED` | Создание фразы |
| `MATERIAL_SUBMITTED` | Отправка материала |
| `EXPORT_CREATED` | Создание экспортного материала |
| `ATELIER_REQUESTED` | Запрос действия Atelier |
| `SHARE_REQUESTED` | Запрос на распространение материала |

Важное замечание:

Наличие определения события в модуле ещё не означает, что событие реально регистрируется и сохраняется.

В проверенной версии `destress-studio.html` v5.2.0 модуль `destressStudioEvents.js` не подключён, а вызовы `track()` отсутствуют.

Поэтому перечисленные события считаются существующей технической заготовкой, но не подтверждённой действующей системой сбора событий.

## 4. Реестр операционных событий

Операционные события относятся к конкретным объектам и действиям.

| Код | Событие | Источник | Назначение | Получатель | Статус |

| OP-01 | Создание ситуации | Посетитель | Регистрация предложения | Supabase | Действует |
| OP-02 | Создание фразы | Посетитель | Регистрация предложения | Supabase | Действует |
| OP-03 | Одобрение публикации | OFFICE | Изменение статуса | Supabase | Частично |
| OP-04 | Скрытие публикации | OFFICE | Изменение статуса | Supabase | Частично |
| OP-05 | Фиксация авторства | Система | Связь новой публикации с автором | Supabase | Целевое |
| OP-06 | Лайк ситуации | Участник | Регистрация поддержки | Supabase | Целевое |
| OP-07 | Лайк фразы | Участник | Регистрация поддержки | Supabase | Целевое |
| OP-08 | Запрос номинации | Автор | Инициация номинации | GY-GY NEWS | Целевое |
| OP-09 | Начало голосования | Система / OFFICE | Запуск клубного голосования | Supabase | Целевое |
| OP-10 | Голос участника | Участник | Регистрация голоса | Supabase | Целевое |
| OP-11 | Завершение голосования | Система | Фиксация результата | GY-GY NEWS | Целевое |
| OP-12 | Признание публикации | Система / OFFICE | Внесение в Книгу почёта | GY-GY NEWS | Целевое |
| OP-13 | Запрос удаления | Автор | Инициация удаления собственной публикации | Серверная логика | Целевое |
| OP-14 | Подтверждение удаления | Сервер | Фиксация результата удаления | OFFICE | Целевое |
| OP-15 | Административное действие | Сотрудник OFFICE | Контроль действий сотрудников | Журнал OFFICE | Целевое |

Операционные события должны иметь однозначную связь с соответствующим объектом и результатом операции.

## 5. Реестр аналитических событий

Аналитические события предназначены для оценки работы локации в целом.

| Код | Событие | Что фиксируется | Цель | Получатель | Статус |

| AN-02 | Использование блока «Случай» | Агрегированное количество действий | Оценка востребованности | Аналитика | Целевое |
| AN-03 | Использование блока «Крепкое слово» | Агрегированное количество действий | Оценка востребованности | Аналитика | Целевое |
| AN-04 | Использование Double Mix | Количество операций | Оценка востребованности | Аналитика | Целевое |
| AN-05 | Обращение к Atelier | Количество запросов | Оценка интереса к Atelier | Аналитика | Частично |
| AN-06 | Экспорт материала | Количество экспортов | Оценка использования функции | Аналитика | Частично |
| AN-07 | Отправка предложения | Количество предложений | Оценка участия | Аналитика | Целевое |
| AN-08 | Динамика публикаций | Количество и изменение статусов | Оценка активности контента | OFFICE | Целевое |
| AN-09 | Динамика лайков | Агрегированное количество | Оценка поддержки публикаций | OFFICE | Целевое |
| AN-10 | Результаты голосования | Агрегированные результаты | Оценка клубного признания | OFFICE | Целевое |

Аналитические события не должны использоваться для восстановления индивидуального поведения участника.
